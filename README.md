# 🃏 ECHO — Blackjack Skill Battle

เกมการ์ดต่อสู้เล่นหลายคนแบบเรียลไทม์ (ไม่มีเจ้ามือ) — จั่วการ์ดเลข **สุ่ม 1–10** ให้แต้มใกล้ 21 สุดโดยไม่เกิน ใครใกล้สุดชนะรอบแล้วได้โจมตี ใครเลือดจริงหมดก่อนตกรอบ เหลือคนสุดท้ายคือแชมป์

## วงจร 1 รอบ = 3 เฟส
1. **เฟสไพ่** (60 วิ): จั่วการ์ดจนพอใจ + ใช้สกิลได้ แล้วกด **เปิดไพ่** (= พร้อม; ไพ่/แต้ม/สกิลของคนอื่นถูกซ่อนจนทุกคนพร้อม)
2. **เฟสสรุปผล**: เปิดแต้มทุกคน + ประกาศผู้ชนะ (แต้มสูงสุดเสมอกัน → สุ่ม 1 คน)
3. **เฟสโจมตี**: ผู้ชนะเลือกเป้าโจมตี (คำนวณจากตัวละคร+สกิล)
> จบ 3 เฟสแล้วขึ้นแบนเนอร์ **"รอบที่ N"** ไปต่อเอง — ไม่ต้องกดยืนยัน · จบเกมเมื่อเหลือผู้รอดคนเดียว

## กติกาต่อสู้
- **พลังชีวิต**: เลือดจริง 3 + เกราะ 2 — เลือดจริง 0 = ตกรอบ / เกราะฟื้น +1 ต้นรอบ
- **ความเสียหาย**: แต้มน้อยสุด −1 (โดนเกราะก่อน) · ผู้ชนะโจมตี −1 เข้าเลือดจริง (แรงขึ้นตามสกิล)
- **หลอดสกิล** (เต็ม 6): จบเทิร์น +1 · ชนะ +2 · โดนเพราะแต้มน้อยสุด +2 · โดนโจมตี +2
- **สกิล**: พื้นฐาน(2)/รอง(4)/ท่าไม้ตาย(6) + สกิลติดตัว(ฟรี) — roster/ค่าคงที่อยู่ใน [characters.js](characters.js), โค้ดเอฟเฟกต์จริงของแต่ละตัวอยู่ใน [characters/](characters/) (ดูหัวข้อ "เพิ่ม/แก้ตัวละคร" ด้านล่าง)

## วิธีเล่น
1. เข้าหน้าเว็บ → กด **เริ่ม**
2. ตั้งชื่อ + เลือกตัวละคร → **เข้าห้องรอ**
3. รอเพื่อน (สูงสุด 7 คน) แล้วกด **เริ่มเกม** หรือกด **เล่นคนเดียว**
4. **จั่วไพ่** เพิ่มได้เรื่อยๆ พอใจแล้วกด **เปิดไพ่**
5. รอทุกคนเปิด หรือหมดเวลา (30 วิ) → ประกาศผู้ชนะ

> เป็นระบบปิด: ไม่มีห้อง/ลิงก์เชิญ ทุกคนเข้าเว็บเดียวกันแล้วเล่นด้วยกันเลย

## สแตก
- **Frontend**: React (Vite) + Tailwind CSS — โฟลเดอร์ `client/` (ธีม ECHO)
- **Backend/Realtime**: Node.js + Express + Socket.IO — `server.js` (เกมเดียวทั้งเว็บ, ยังไม่มีระบบห้อง)

## รันในเครื่อง

### โหมดพัฒนา (dev — แก้แล้วเห็นผลทันที) ใช้ 2 เทอร์มินัล
```bash
# เทอร์มินัล 1: เซิร์ฟเวอร์เกม
npm install
npm start            # ที่ http://localhost:3000

# เทอร์มินัล 2: React dev server (proxy socket ไป :3000 ให้เอง)
npm run client       # เปิด http://localhost:5173
```
เปิดหลายแท็บที่ :5173 เพื่อจำลองหลายคน

### โหมดจริง (prod — build React แล้วให้เซิร์ฟเวอร์เสิร์ฟเอง)
```bash
npm run build        # ติดตั้ง+build client -> client/dist
npm start            # เปิด http://localhost:3000 (server เสิร์ฟ React build ให้อัตโนมัติ)
```
> ต้อง `npm run build` ก่อนเสมอในโหมด prod (ไม่มีเวอร์ชัน fallback อื่นอีกแล้ว)

## ตัวแปรสภาพแวดล้อม (environment variables)
ทุกตัวมีค่า default ที่สมเหตุสมผล ไม่ตั้งอะไรเลยก็รันได้ปกติ — ดูรายละเอียด/ตัวอย่างใน [.env.example](.env.example):
- `PORT` — พอร์ตที่เซิร์ฟเวอร์รัน (Render/PaaS กำหนดให้เองอัตโนมัติ)
- `ALLOWED_ORIGIN` — จำกัด origin ที่เชื่อมต่อ socket.io ได้ (ควรตั้งตอน deploy จริง)
- `ASSET_BASE_URL` — redirect ไฟล์สื่อทั้งหมดไป Cloudflare R2 แทนการเสิร์ฟจากเครื่อง (ครอบคลุม `/characters`, `/item`, `/overload_force`, `/theme_song`, `/effect_sound`, `/image`) — **ต้องอัปโหลดครบทุกโฟลเดอร์ขึ้น R2 ก่อน** แล้วค่อย deploy ไม่งั้นเพลง/พื้นหลังจะ 404
- `RECONNECT_GRACE_MS` — เวลาที่กันที่ไว้ให้ผู้เล่นหลุดกลับมาต่อเกมได้ (ค่าเริ่มต้น 60 วินาที)

## ใส่รูป/วิดีโอ/เพลงตัวละคร
รูป/วิดีโอ/เพลงของแต่ละตัวละครอยู่ที่ `client/public/characters/<characterId>/` (โครงสร้างย่อยตามที่แต่ละตัวละครใช้จริง เช่น `profile/`, `skill1/`) — **ไฟล์เหล่านี้ไม่ได้ track ใน git แล้ว** (ย้ายไปเก็บบน Cloudflare R2 แทน ดู `ASSET_BASE_URL` ด้านบน) ถ้ายังไม่มีไฟล์ในเครื่องและไม่ได้ตั้ง `ASSET_BASE_URL` เกมจะใช้อีโมจิสัตว์/สัญลักษณ์แทนให้อัตโนมัติ (`client/src/data/avatars.js`)

## ขึ้น Render (PaaS)
1. อัปโหลดโค้ดขึ้น GitHub
2. ไปที่ Render → **New +** → **Web Service** → เชื่อม repo
3. ตั้งค่า:
   - **Environment**: `Node`
   - **Build Command**: `npm install && npm run build`
   - **Start Command**: `npm start`
4. กด **Create Web Service** → รอ deploy เสร็จ
5. เอา URL ที่ได้ (เช่น `https://xxx.onrender.com`) ส่งให้เพื่อนเข้าเล่นพร้อมกัน

> Render จะกำหนดพอร์ตให้เองผ่าน `process.env.PORT` (เซิร์ฟเวอร์รองรับแล้ว)

### ประหยัด bandwidth
โควตา bandwidth ของ PaaS หมดเร็วมากถ้าปล่อยตามค่าเริ่มต้น — สองจุดที่กินหนักที่สุดและวิธีคุม:
- **ไฟล์สื่อ (HTTP)** — ตั้ง `ASSET_BASE_URL` ให้ครบ แล้วอัปโหลด `/characters`, `/item`, `/overload_force`,
  `/theme_song`, `/effect_sound`, `/image` ขึ้น R2 (R2 ไม่คิดค่า egress) เหลือให้ server เสิร์ฟแค่ `index.html`
  กับ bundle ของ vite เท่านั้น · เพิ่มไฟล์สื่อใหม่เมื่อไหร่ ต้องอัปขึ้น R2 ด้วยทุกครั้ง ไม่งั้นของจริงจะ 404
- **ขนาดไฟล์** — ไม่กระทบโควตา bandwidth แล้ว (R2 ฟรี) แต่ยังกระทบเวลาโหลดหน้าแรกบนมือถือ · สแปลช/พื้นหลัง/
  โลโก้เก็บเป็น `.webp` (เล็กกว่า png เดิม ~10 เท่า) · mp3 ในโฟลเดอร์ `theme_song` เข้ารหัสที่ ~120 kbps อยู่แล้ว
  ไม่ควร re-encode ซ้ำเพราะเสียคุณภาพโดยแทบไม่ได้ขนาดคืน
- **ข้อมูลเกม (WebSocket)** — ตัวจับเวลาส่งแค่ event `tick` (ตัวเลขนับถอยหลังล้วน ๆ) ทุกวินาที และ broadcast
  state ตัวเต็มทุก `RESYNC_EVERY` วินาทีเท่านั้น (`server.js`) · socket.io เปิด `perMessageDeflate` ไว้แล้ว
  ถ้าจะเพิ่มฟิลด์ใหม่ลง state อย่าลืมว่ามันถูกส่งให้ผู้เล่นทุกคน — เลี่ยงการยัดข้อความยาว ๆ ที่ไม่เปลี่ยนค่า
  (วัดจริงกับแมตช์ 6 คนที่นั่งเฉย ๆ: ก่อนแก้ 720 MB/ชม. หลังแก้ 10.4 MB/ชม.)
- **bundle (HTTP)** — เปิด `compression()` ไว้แล้ว js/css ของ vite ถูก gzip ก่อนส่ง (637 KB -> 175 KB)

```

characters.js          roster ตัวละคร (id/ชื่อ/รูปโปรไฟล์/ชื่อสกิล) + สีตำแหน่ง P1-P6 — ไม่ใช่ที่แก้เอฟเฟกต์สกิล (ดูด้านล่าง)
characters/             โค้ดเอฟเฟกต์/พาสซีฟจริงของแต่ละตัวละคร แยกไฟล์ต่อคน (server.js require ผ่าน characters/index.js)
  index.js              รวม CHAR_HOOKS — ทุกตัวละครต้องลงทะเบียนที่นี่
  _universal_status.js  ระบบบัฟ/ดีบัฟกลางที่ตัวละครไหนก็ใช้ร่วมกันได้ (ไม่ใช่ตัวละคร ไม่มี id)
                        เช่น เสริมพลัง/คุ้มครอง/ต้านสถานะผิดปกติ/หลบหลีก/ลุกไหม้/เนตรมณะ (โอกาสสังหาร 20%)
  <characterId>.js      เอฟเฟกต์สกิล/พาสซีฟของตัวละครนั้นๆ ← แก้ตัวละครที่นี่
tests/                  test suite — `npm test` (Node built-in test runner, ไม่ต้องติดตั้ง dependency เพิ่ม)
package.json            สคริปต์ start / build / client / test
client/                React (Vite) + Tailwind — ธีม ECHO
  src/
    App.jsx            คุมลำดับหน้าจอ + รับ roster/positions จาก server
    socket.js          เชื่อม Socket.IO
    index.css          Tailwind + ธีมสี ECHO + glitch/halftone/อนิเมชัน
    data/              avatars.js (อีโมจิสำรอง), positions.js (สี P1-P6)
    screens/           Splash / Setup(ชื่อ+ตำแหน่ง) / CharacterSelect / Lobby / Game
    components/        Card / Button / VolumeControl

  dist/                ผลลัพธ์ build (server เสิร์ฟอันนี้ในโหมด prod)
```

## เพิ่ม/แก้ตัวละคร
1. **ข้อมูล roster** (ชื่อ, รูปโปรไฟล์, ชื่อสกิล, ค่าคงที่ที่ engine กลางต้องรู้) แก้ที่ [characters.js](characters.js)
2. **เอฟเฟกต์สกิล/พาสซีฟจริง** แก้ที่ไฟล์ของตัวละครนั้นใน [characters/](characters/) (เช่น `characters/tohno.js`) — แต่ละไฟล์ export ฟังก์ชันที่ `server.js` เรียกผ่าน `CHAR_HOOKS.<id>.<method>(engine, ...)` ดูตัวอย่างจากไฟล์ตัวละครที่มีอยู่แล้วเป็นแนวทาง — ตัวละครใหม่ต้องเพิ่ม `require`+เข้า array ใน [characters/index.js](characters/index.js) ด้วย
3. ถ้าเอฟเฟกต์นั้นเป็นกลไก**กลาง**ที่ตัวละครไหนก็ควรใช้ร่วมกันได้ (เช่น "ดาเมจเพิ่ม N", "ห้ามใช้สกิล N เทิร์น") ให้ใช้ระบบสถานะ universal ใน [characters/_universal_status.js](characters/_universal_status.js) แทนการสร้าง key สถานะใหม่เฉพาะตัว
